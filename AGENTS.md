Инструкции для ИИ-ассистента (Cursor, Claude Code и т.п.). Человеку тоже

## Коротко о проекте

**SimpleGeo** (`simplegeo.ru`) — бесплатный тренажёр подготовки к ОГЭ по
географии. React 18 + Vite 5 + Tailwind 3, статика, **бэкенда нет**. Хостинг —
Selectel S3 (Россия). Пользователь — предметный эксперт по географии, автор
Telegram-канала `prostayageo`; код для него инструмент, а не профессия.

Язык общения и комментариев в коде — **русский**.

## Правила, которые важнее всего

1. **Никогда не коммить и не пушить без явного разрешения — каждый раз
   отдельно.** Порядок такой: сделал → показал на localhost → спросил →
   только потом коммит. Разрешение на один коммит не распространяется на
   следующий.
2. **Секреты не ходят через переписку.** Токены, ключи и пароли пользователь
   вводит сам. Ключи S3 живут в GitHub Secrets (`S3_KEY_ID`, `S3_SECRET`,
   `S3_BUCKET`, `S3_ENDPOINT`), в коде их быть не должно.
3. **`src/data.js` руками не править.** Это автогенерация (3 МБ, 2353
   задания). Правки идут в соседний репозиторий `~/Desktop/fipi_parser/`
   (Python-пайплайн), оттуда перегенерация. Ручная правка `data.js`
   затрётся при следующей генерации.
4. **Перед правкой — прогнать тесты, после — тоже.** `npm test`, 97 тестов.

## Бренд-система — обязательна для любой правки интерфейса

Источник истины по визуальному языку — **[docs/brand/BRAND_GUIDELINES.md](docs/brand/BRAND_GUIDELINES.md)**.
Прочитай его перед тем, как трогать хоть один класс в JSX. Бренд — не пожелание,
а ограничение архитектуры проекта.

1. **Бренд-система — source of truth.** Перед изменением UI сначала ищи
   существующий токен, компонент или приём и переиспользуй его.
2. **Только токены.** Цвета — `bg-paper`, `text-ink`, `bg-brand`, `border-line`…
   или `var(--sg-…)`. Запрещены стандартная палитра Tailwind (`slate-*`,
   `green-*`, `rose-*`, `amber-*`…), `#hex` в компонентах и градиенты.
3. **Не создавай новые цвета.** Даже «чуть другой зелёный» для наведения.
   Зелёный в интерфейсе один — `#17784A` (`brand`).
4. **Не подключай другие шрифты** и не пиши `style={{ fontFamily }}`. Science
   Gothic 800 — заголовки (от 20 px), Onest — текст, Tektur 600 — цифры и метки.
5. **Не заменяй брендовые ассеты самодельными.** Логотип — только файлы из
   `public/brand/logo/`, иконки — только `<Icon name="…" />`, маскот — только
   `MASCOT` из `src/brand/mascot.js`. Эмодзи вместо иконок нельзя.
6. **Новые компоненты — из существующих:** `PrimaryButton` (одна на экран),
   `SecondaryButton`, `Chip`, `TaskCard`, `Shell`, `Icon`, состояния `ANSWER`.
7. **Цвет не работает один.** Верно/неверно, сильный/слабый — всегда ещё словом
   или иконкой. Выбранный, но не проверенный ответ — чернильный, **не зелёный**.
8. **Новый токен нужен?** Сначала убедись, что без него никак. Потом добавь его
   в `src/brand/tokens.css` **и** `tailwind.config.js` (значения совпадают) и
   строку в `BRAND_GUIDELINES.md`. Только потом используй.
9. **Конфликт с брендом — называй явно.** Если задача требует того, чего бренд
   не разрешает, скажи об этом, а не обходи правило молча.
10. **После правки UI проверь**, что не нарушено ничего из списка выше (команды
    в §11 гайдлайнов должны давать пустой вывод), и посмотри на 375 и 1440 px.
11. **Изолинии лежат фоном под всем сайтом.** Новый экран, где решают задания или
    показывают учебную карту, обязан вызвать `useTaskScreen(true)` из
    `src/brand/PageBackground.jsx` — иначе линии окажутся под текстом задания
    (брендбук это запрещает).

Радиусы в теме **переопределены**: `rounded-md` = 10 px (кнопки, поля, варианты),
`rounded-lg` = 12 px (карточки), `rounded-xl` = 16 px — не как в обычном Tailwind.

## Грабли, на которые уже наступали

### Файл в `public/` нельзя заменить под тем же именем

Деплой отдаёт всё, кроме `index.html` и `weekly-variants.json`, с заголовком
«хранить год, не перепроверять» (`.github/workflows/deploy.yml`). У файлов из
`src/` имя при сборке содержит хэш и меняется вместе с содержимым; у файлов из
`public/` — нет. Перезаписал `public/что-то.png` — вернувшиеся посетители год
видят старую картинку. Проверено на живом сайте 24.09.2026: старый
`/mascot/welcome.png` отдаётся с `max-age=31536000, immutable`, так что замена
маскота под тем же именем до этих посетителей бы не дошла. Поэтому маскот и узор изолиний лежат в `src/brand/` и
импортируются. Картинку, которая может меняться, — в `src/`; если файл в
`public/` всё же меняется — новое имя.

### Перегенерация `data.js` ухудшает данные

`fipi_parser/pipeline/06_generate_data_js.py` **не безопасно перезапускать
просто так**. В текущем `data.js` есть 22 задания «определите долю … в %», где
текст вопроса и таблица поправлены вручную, а в `fipi_final_merged.xlsx` лежит
старый вариант — с таблицей, вшитой в текст вопроса одним нечитаемым абзацем.
Перегенерация молча откатит эти 22 задания к худшей версии.

Если всё же надо перегенерировать: сохранить текущий `data.js`, сгенерировать,
сравнить **по заданиям** (не построчно — весь массив `TASKS` лежит в одну
строку, обычный diff бесполезен), вернуть те 22 вручную. Потом `npm test`.

### Бот коммитит прямо в `main`

`weekly-variants.yml` по понедельникам генерирует варианты недели и коммитит
`public/weekly-variants.json` в `main` от имени бота. Локальная копия после
этого отстаёт. Если `tests/weekly.test.js` краснеет на свежести файла —
сначала `git fetch && git log origin/main`, а не чинить генератор.

### Сравнение ответов — самое хрупкое место

`norm()` в `src/utils.js` решает, засчитать ответ ученику или нет. Там уже были
две дорогие ошибки: стиралась десятичная запятая («14» засчитывалось вместо
«1,4»), и не приводилось длинное тире к минусу (верный ответ считался ошибкой).
Обе закрыты тестами с пометкой `[РЕГРЕССИЯ]`. **Если такой тест покраснел —
чинить код или данные, а не тест.**

## Структура

```
src/
├── App.jsx                 маршруты и верхнее меню
├── pages/                  экраны; Trainer.jsx экспортирует общие UI-кирпичики
│   ├── Trainer.jsx         /tasks — тренажёр по разделам (главная)
│   ├── Variant.jsx         /tasks/variant — полный вариант из 30 заданий
│   ├── ByPosition.jsx      /tasks/by-number — тренировка по номеру 1-30
│   ├── WeeklyVariants.jsx  /tasks/weekly — 5 вариантов недели
│   ├── Demo2027.jsx        /tasks/demo-2027 — демо ОГЭ 2027 одним свитком
│   ├── Diagnostic.jsx      /tasks/diagnostic — мини-диагностика, отчёт по блокам
│   ├── About.jsx  Course.jsx  NotFound.jsx
├── brand/                  бренд-система: tokens.css, fonts.css, fonts/, Icon.jsx,
│                           PageBackground.jsx (изолинии фоном + useTaskScreen),
│                           mascot.js + mascot/, iso/page.svg
├── VariantRunner.jsx       общий движок прохождения варианта
├── variantBuilder.js       сборка варианта по структуре реального КИМ
├── diagnosticBuilder.js    сборка набора мини-диагностики (19 заданий)
├── positionClassifier.js   какое задание может стоять на позиции 1-30
├── utils.js                проверка ответа, norm(), seededRng()
└── data.js                 банк заданий (автогенерация, не править)
```

Пять групп позиций делят общий контекст и берутся целиком, разрывать нельзя:
**9-12** (топоплан), **5-6** (погодная карта), **16-17** (данные наблюдений),
**23-24** (демография), **28-30** (текст).

## Команды

```bash
npm run dev     # локально → http://localhost:5173
npm test        # 97 тестов, должны быть все зелёные
npm run build   # сборка в dist/
```

Тесты в `tests/`: `utils` (проверка ответов), `dataset` (целостность банка),
`variantBuilder` (структура варианта), `weekly`, `demo2027`, `diagnostic`,
`formatQuestionText` (срез бланковых хвостов в тексте вопроса).

---

## Деплой

`git push` в `main` → GitHub Actions собирает и заливает `dist/` в Selectel S3.
Отдельной команды деплоя нет: **пуш в main = выкладка на живой сайт**. Поэтому
правило №1 из списка выше.
